### Проблематика:

Технологическая база компании не готова полностью к обработке больших объемов данных, характерных для пиковых периодов
поставок и строительного сезона.

- В периоды активного строительства — особенно весной и летом — резко возрастает количество операций, связанных с
  движением товарных остатков, оформлением заявок на поставку и внутренней логистикой между складами. В это время
  фиксируются обращения от сотрудников, что отчёты по остаткам «висят», обновления позиций происходят с большой
  задержкой либо вовсе не применяются.
- Замедляется работа ERP-интерфейса при формировании складских заданий и приёме материалов.
- В IT-инфраструктуре отсутствуют средства мониторинга системы. Есть только логи в файл и стандартный мониторинг
  ресурсов VM и WildFly.
  Сейчас IT-инфраструктура — это монолит, предоставляющий пользовательский интерфейс, куда сотрудник склада загружает
  отчёт об остатках и перемещениях в конце рабочей смены.

**Стек**

**Фронтенд**: Angular, WebSockets.
**DevOps**: Docker, Docker Compose, GCP.

### <a name="_qmphm5d6rvi3"></a>**Решение**

Использовать Java Spring Batch. Является распространенной ETL-системой на Java.

##### Плюсы:

- Команда имеет опыт работы с Java
- Распространенный инструмент оркестрации
- Имеет высокую производительность
- Создание процессов (Job) выполняется на языке Java
- Имеет очень широкий набор готовых коннекторов к различным источникам данных:
    - BigQuery
    - Redshift
    - Kafka
    - Spark
- Позволяет использовать API для запуска процессов
- Позволяет использовать CRON-выражения для запуска процессов

##### Минусы:

- Отсутствует UI для настройки.
- Может потребоваться внешний оркестратор для запуска задач
- Высокий порог входа для реализации процессов.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

#### Airflow

Является одним из самых распространенных Open Source оркестраторов.

##### Плюсы:

- Очень распространенный инструмент оркестрации
- Имеет sdk для создания собственных операторов (шаблонов задач)
- Имеет очень широкий набор готовых коннекторов к различным источникам данных

##### Минусы и риски:

- У команды нет опыта
- Требовательность к инфраструктуре.
- Сложность в конфигурировании worker и scheduler, требуется тонкая настройка
- Неявные зависимости. Одни задачи могут зависеть от результатов выполнения других, но эти зависимости не явно указаны в DAG
