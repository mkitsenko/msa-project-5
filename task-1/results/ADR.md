### Проблематика:

Маркетинговый отдел планирует расширенно обрабатывать данные клиентов, объединяя их из разных источников,
и формировать отчёты. В работе используются данные из разных источников: файловое хранилище CSV-файлов, содержащих
статусы доставок пользователей, таблицы PostgreSQL с информацией о заказах, данные о платежах по заказам,
расширенные данные о пользователях и данные из Kafka с цепочкой событий по модификации заказов.
Текущая система обработки не справляется с нагрузкой и запрашиваемым функционалом.
Поэтому необходим выбрать и обосновать технологическое решение для пакетной обработки данных.

### <a name="_qmphm5d6rvi3"></a>**Решение**

Использовать Apache Airflow. Является одним из самых распространенных Open Source оркестраторов.
Содержит широкий набор функциональности. Позволяет создавать процессы оркестрации в виде Directed Acycled Graph (DAG).

##### Плюсы:
- Команда имеет опыт работы с Apache Airflow
- Очень распространенный инструмент оркестрации
- Создание процессов выполняется на языке Python
- Имеет sdk для создания собственных операторов (шаблонов задач)
- Имеет очень широкий набор готовых коннекторов к различным источникам данных:
  - BigQuery
  - Redshift
  - Kafka
  - Spark
- Имеет BranchOperator для ветвления процессов
- Имеет встроенные механизмы: fallback и retry для выполнения задач
- Имеет широкий набор для операторов (задач) для event-base сценариев:
  - FileSensor - ожидания событий работы с файлами
  - TaskSensor - ожидания выполнения задач для создания и выполнения асинхронных задач
- Имеет helm chart от авторов инструмента для развертывания инструмента в Kubernetes
- Позволяет использовать API для запуска процессов
- Позволяет использовать CRON-выражения для запуска процессов


##### Минусы:

- Требовательность к инфраструктуре.
- Сложность в конфигурировании worker и scheduler, требуется тонкая настройка
- Неявные зависимости. Одни задачи могут зависеть от результатов выполнения других, но эти зависимости не явно указаны в DAG
